# 微信云托管（CloudRun）部署指南 · 课序选课排课系统

> 本指南是基于项目内置技能 `wechat-cloudrun-deploy` 的**本项目专属落地步骤**。
> 核心收益：小程序后端走微信内网通道，**免 ICP 备案、免 HTTPS 证书、免服务器域名白名单**。

---

## 1. 前置准备

1. 确认小程序已完成**主体认证**，AppID 已知（通过 `server/src/config.js` 读取环境变量 `APPID` / `APPSECRET`，详见 `server/.env.example`）。
2. 登录微信云托管或腾讯 CloudBase 控制台，并按控制台提示开通按量服务；套餐、免费额度和计费以控制台实时信息为准。
3. 记录两个标识：
   - **环境 ID**（Environment ID，形如 `prod-xxx`）
   - 新建服务后的**服务名称**（本指南建议用 `kexu-backend`）

---

## 2. 部署后端到云托管

1. 控制台「服务管理」→ **新建服务**，服务名称填 `kexu-backend`（记下来，对应 `config/cloudrun.js` 的 `service`）。
2. **部署方式选「代码上传」**：上传仓库根目录（包含根目录 `Dockerfile`、`server/`、`docs/schema.sql` 与 `admin-console.html`），平台自动构建镜像。不要只上传 `server/`，否则容器无法包含数据库表结构和管理后台。
3. 运行参数：实例规格选最小档即可；成本优先时最小实例数设为 `0`，最大实例数设为 `2`。
4. **注入环境变量**（服务设置 → 环境变量）：
   - `PORT=8080`（须与部署命令的 `--port 8080` 一致）
   - `APPID`、`APPSECRET`（与 `server/src/config.js` 一致；config.js 同时兼容 `WECHAT_APPID` / `WECHAT_SECRET` 别名）
   - `TOKEN_SECRET`（使用 `openssl rand -hex 32` 生成）
   - 个人版/免费版：`DB_MODE=cloudbase_mysql`、`CLOUDBASE_ENV_ID=你的环境 ID`
   - 标准版及以上如需 MySQL 内网直连：`DB_MODE=mysql`、`DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD`、`DB_NAME`
5. **网络访问**：保持公网 HTTPS 访问开启，供 `/admin` 管理后台使用；小程序仍可通过 `wx.cloud.callContainer` 调用同一服务。
6. 查看部署/运行日志，确认容器启动成功、健康检查通过。

> 本地自测镜像（可选，需本机装 Docker）：
> ```bash
> cd kexu
> docker build -t kexu:local .
> docker run -p 8080:80 kexu:local
> curl http://127.0.0.1:8080/api/health   # 应返回 {"status":"up"}
> ```

## 3. 小程序端切换为云托管通道

编辑 `miniprogram/config/cloudrun.js`：

```javascript
module.exports = {
  enabled: true,                 // ⚠️ 本地联调保持 false；上线改为 true
  env: 'prod-xxxx',              // ← 换成你的云托管环境 ID
  service: 'kexu-backend',       // ← 与控制台服务名称一致
};
```

说明：
- `enabled: false` 时，请求走 `wx.request` + `http://localhost:3000`，即你现在的模拟器联调方式，**完全不受影响**。
- `enabled: true` 时，请求走 `wx.cloud.callContainer`，流量经微信内网到 `kexu-backend` 服务，无需配域名白名单。
- 微信后台「设置 → 功能设置 → 基础库最低版本」需设为 **≥ 2.23.0**（云托管要求）。

---

## 4. 联调与发布

1. 开发者工具编译 → **真机预览**，验证课程列表/报名/登录链路。
2. 确认 `wx.cloud.init()` 已执行（无 `Cloud API isn't enabled` 报错；若偶发，属 init 异步未完成，已在 `app.js` 安全 try/catch，可封装重试）。
3. 真机验证通过后，开发者工具**上传代码** → 小程序后台**提交审核** → 审核通过**发布**。
4. 上线后观察云托管监控（QPS、错误率、实例负载）。

### 联调排错速查
- 404 / 无响应：核对 `service` 服务名与后端路由（path 形如 `/api/courses`）。
- 请求过大：单请求体上限 100KiB，大文件改走对象存储。
- 超时：上限 15 秒，长任务须异步化。
- 登录链路：后端现有 `code2Session`（AppSecret 换 openid）在云托管容器内仍可正常调用公网；云托管内网还会在 header 注入 `x-wx-openid`，后续如需可改用此方式免 code2Session。

## ⚠️ 5. 数据持久化

后端 `store.js` 支持三种持久化后端，由 `DB_MODE` 切换：

- **`DB_MODE=cloudbase_mysql`（个人版/免费版推荐）**：使用 CloudBase SDK 网关访问环境内置 MySQL，把完整运行时快照原子写入 `app_snapshots` 的 A/B 两个滚动槽位，始终保留上一份有效快照。不需要 VPC，也不需要开启 MySQL 公网地址。适合当前体量；数据明显增长后再迁移到关系表直连模式。
- **`DB_MODE=mysql`**：使用 MySQL / 云数据库。启动跑 `docs/schema.sql` 建表（幂等），库为空则写种子、否则从库加载；每次写操作经事务批量 `flush` 落库。CloudBase MySQL 生产内网直连要求云托管套餐支持 VPC。
- **未配置 `DB_HOST`（默认）**：回退到文件模式（`data.json` 兜底），适合本地零依赖演示。

当前个人版部署在云托管「环境变量」中注入：

```
DB_MODE=cloudbase_mysql
CLOUDBASE_ENV_ID=app-d2gqxo7iof3a0d7ce
CLOUDBASE_MYSQL_TABLE=app_snapshots
```

如果以后升级套餐并切换到 MySQL 内网直连，再改为：

```
DB_HOST=你的MySQL内网地址
DB_PORT=3306
DB_USER=你的用户名
DB_PASSWORD=你的密码
DB_NAME=kexu
```

表结构与内存模型逐字段一致，见 `docs/schema.sql`；连接串通过环境变量注入，源码不含任何凭据。

重置演示数据：

- MySQL 模式：`npm run reset-db`（清空所有表，下次启动重新种子）
- 文件模式：`npm run reset`（备份并删除 data.json）

## 6. 交付物清单（本项目）

- 根目录 `Dockerfile` + `.dockerignore` —— CloudBase Run / Git 仓库部署入口
- `server/Dockerfile` —— 显式指定 Dockerfile 时的等价构建入口（构建上下文仍为仓库根目录）
- `admin-console.html` —— 由后端同源暴露在 `/admin`
- `server/src/server.js` 的 `GET /` 健康检查
- `server/src/store.js` —— MySQL / 文件双持久化存储层
- `docs/schema.sql` —— 与内存模型对齐的 MySQL 8 建表脚本
- `server/.env.example` —— 数据库连接环境变量样例
- `miniprogram/config/cloudrun.js` —— 云托管开关与标识
- `miniprogram/utils/request.js` —— 双模式请求层
- `miniprogram/app.js` —— `wx.cloud.init()` 全局初始化
- 本指南 `docs/云托管部署指南.md`

成本提示：云托管和 Serverless MySQL 通常按量计费；上线前在控制台设置预算与告警，并以控制台实时价格为准。
