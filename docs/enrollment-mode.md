# 自主报名模式

学生在课程开放时自行报名；报名成功后立即进入“我的课程”和课表。未报名不触发志愿分配或自动调剂。

管理端可设置课程容量、报名起止时间、教师和排课。报名范围四选一：全体学生、指定年级、指定班级、指定教学组。教学组仅是预先保存的班级集合，没有独立开放状态，不限制班级数量或要求绑定至少两门课程。每人选课上限、分类上限、退课后是否可重新报名在“规则与记录”设置。

未填写时间时由课程的开放/停止按钮控制；开始时刻可报名，截止时刻开始拒绝报名和学生自行退课。截止后由老师办理退课。学生可不参加，不要求名额覆盖全部学生。

## Excel 名单

“报名管理 → 导出全校报名名单”生成一个 `.xlsx`，包含两个工作表：

- 已报名：学号、姓名、年级、班级、课程、任课老师、上课时间、场地、报名时间。每个有效报名一行，多门课程会有多行。
- 未报名：学号、姓名、年级、班级、状态。没有任何有效报名的在籍学生每人一行，含退课后未另选课程的学生。

两张表在同一次服务端请求中生成，不受报名列表的搜索条件影响。接口按教学组筛选时只筛选学生范围，统计这些学生的全部有效报名。学号为文本，保留前导零；空名单仍输出表头。

## 现有数据与上线

现有课程、教学组、学生和已生效报名保持原样。历史志愿和分配数据保留，但志愿提交、模拟和发布写接口返回 410，防止覆盖抢课名单。

旧教学组的状态不再控制报名，部署前须核对课程开放状态、容量及起止时间。旧课程关联会显示为普通教学组范围；如果还指定了年级或班级，会保留交集。保存课程后移除旧隐式关联，以新范围为准；改成全体学生后不再附加教学组限制。

## 一致性与验证范围

当前仍是单应用进程，未实现 3000 QPS 的 Redis 预占和异步队列方案，不能仅通过复制应用容器或启动多个 Node 进程扩容。内存镜像及整库快照持久化需要后续拆除，才能支持多实例。

报名之间按学生、课程串行化；管理写操作等待在途报名完成，报名也等待管理保存完成，避免整库快照覆盖逐行报名写入。MySQL 在事务内检查已有报名并条件增加人数，写入或唯一键冲突时回滚；成功提交后才响应报名成功。生产 MySQL 初始化失败会停止服务，不再降级为临时文件数据库。

测试入口：`npm test`；构建：`npm run build:web`。

新增 HTTP 回归使用临时文件数据库，覆盖 60 人争抢 20 名额、重复请求、跨课程并发上限与冲突、时间限制、退课、管理代报名、名单分类及重启。MySQL 故障用连接注入验证回滚控制，**不等于真实 MySQL 集成压测**。Excel 测试实际写出并重新读取 XLSX。正式大规模使用前还需要在隔离 MySQL/Redis 环境验证压力与故障恢复，不能把限流拒绝算作成功吞吐。

本地界面预览可运行 `node server/test/helpers/preview-enrollment.js`。它只创建临时测试目录，退出时清理；不连接生产库、不载入现有本地学生数据。
